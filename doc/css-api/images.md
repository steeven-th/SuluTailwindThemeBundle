# Images — CSS API

Every content image is rendered through the unified partial
[`blocks/common/_image.html.twig`](../twig-reference.md#partial-blockscommon_imagehtmltwig),
which emits a `<picture>` with progressive `avif`/`webp` sources and a fallback
`<img>`. This page documents the two families of static utility classes the
partial (and the blocks that crop images) rely on.

> Conventions: `iw-` prefix for ratio boxes, framework-style `focus-*` for focus
> positioning. See [`../css-conventions.md`](../css-conventions.md).
>
> These classes are **hand-written in `assets/styles/app.css`**, not generated by
> Tailwind — they never need to be added to the `@source inline(...)` safelist.

---

## Aspect-ratio boxes

Applied on the `<picture>` wrapper when the `ratio` param is set. The image
inside fills the box with `object-cover`, so the ratio is enforced without any
inline `style="aspect-ratio"`.

| Class | Ratio |
|-------|-------|
| `.iw-ratio--16-9` | `16 / 9` |
| `.iw-ratio--4-3` | `4 / 3` |
| `.iw-ratio--3-2` | `3 / 2` |
| `.iw-ratio--1-1` | `1 / 1` |
| `.iw-ratio--3-4` | `3 / 4` |
| `.iw-ratio--2-3` | `2 / 3` |
| `.iw-ratio--9-16` | `9 / 16` |
| `.iw-ratio--21-9` | `21 / 9` |
| `.iw-ratio--a` | `600 / 849`, the A series (A4, A5 posters, 1:√2) in the pixels of `iw_theme_a_series` |

The partial normalises the `ratio` param, so `'16/9'`, `'16:9'` and `'16-9'` all
resolve to `.iw-ratio--16-9`. A template passing a ratio of its own only needs a
`.iw-ratio--X-Y` rule in your stylesheet, no Twig change.

### Ratios an editor can pick

The ratio selects of the admin (Cards tab, page hero, galleries, text and
images, article listing pages, article list and carousel blocks) all list one
catalogue, `ImageRatioCatalog`. It ties each ratio to the image format cut to
it and to its box, and Twig reads it through
[`iw_sulu_tailwind_theme_image_ratio()`](../twig-reference.md#iw_sulu_tailwind_theme_image_ratiovalue-fallback).

**Adding a ratio from a project** takes a single format in the project's
`config/image-formats.xml`, whose key starts with `iw_ratio_`:

```xml
<format key="iw_ratio_cinema">
    <meta>
        <title lang="en">Cinema 21:9</title>
        <title lang="fr">Cinéma 21:9</title>
    </meta>
    <scale x="2100" y="900" mode="outbound"/>
</format>
```

- Every ratio select offers it, labelled with the format's `<title>` in the
  admin's language (English, then any title, then the key as fallbacks).
- The box is `.iw-ratio--cinema` (the rest of the key, `_` turned into `-`),
  drawing `aspect-ratio: 2100 / 900` from the `scale`. It is written into the
  compiled theme stylesheet, so run `bin/console iw-sulu:theme:compile` once the
  format is added, then `cache:clear` for the admin to list it.
- [Width variants](../twig-reference.md#width-variants-and-srcset) work as for any format:
  `iw_ratio_cinema_w700`, declared `internal="true"`.
- The prefix is the opt-in. A cropped format without it (an avatar, a hero
  banner) never shows up in the selects.

A prefixed format that cannot draw a box is left out of the selects, and
`bin/console iw:tailwind-theme:check` says why: a `scale` without a height, a
scale that does not crop (`mode="inset"`), a key with characters other than
lowercase letters, digits and underscores, or a name whose box class is already
taken (`iw_ratio_16_9`).

A **bundle** ratio is added in `ImageRatioCatalog::RATIOS`, with its format in
the bundle's `config/image-formats.xml` and its `.iw-ratio--*` rule in
`app.css`. `ImageRatioContractTest` fails when one of the three is missing, and
when a select lists ratios by hand instead of the catalogue.

## Focus point

Sulu stores a focus point on every media (a 3×3 grid). It is **already applied
server-side** when Sulu crops an outbound format, so the generated thumbnail is
focus-aware. These classes are a **client-side safety net** for the cases where
the crop happens in the browser — an image with `object-cover` that does not
match a server format exactly, or a CSS `background-image`.

Emitted automatically by the image partial (`object-position`) and available for
CSS backgrounds via
[`iw_sulu_tailwind_theme_focus_class(x, y, 'bg')`](../twig-reference.md#iw_sulu_tailwind_theme_focus_classfocuspointx-focuspointy-mode)
(`background-position`).

Grid values: `0` = left/top, `1` = center, `2` = right/bottom.

| `<img>` (object-position) | Background (background-position) | Position |
|---------------------------|----------------------------------|----------|
| `.focus-img-0-0` | `.focus-bg-0-0` | left top |
| `.focus-img-1-0` | `.focus-bg-1-0` | center top |
| `.focus-img-2-0` | `.focus-bg-2-0` | right top |
| `.focus-img-0-1` | `.focus-bg-0-1` | left center |
| `.focus-img-1-1` | `.focus-bg-1-1` | center center |
| `.focus-img-2-1` | `.focus-bg-2-1` | right center |
| `.focus-img-0-2` | `.focus-bg-0-2` | left bottom |
| `.focus-img-1-2` | `.focus-bg-1-2` | center bottom |
| `.focus-img-2-2` | `.focus-bg-2-2` | right bottom |

When the media has no focus point, no class is emitted (the server-side centred
crop is used as-is).

## avif / webp

The partial reads `media.thumbnails['<format>.avif']` and `['<format>.webp']`.
Sulu **always** exposes both keys (its `ImagineImageConverter` lists `webp` and
`avif` unconditionally), encoding each on demand when the URL is first requested.

- **WebP** is served on any modern GD / Imagick build, so its `<source>` is
  always emitted.
- **AVIF** is served only where the server imagine driver was built with AVIF
  support. Because `<picture>` does not retry a source that fails to load, the
  avif `<source>` is gated on the theme toggle **Default settings → Images → “Serve
  images as AVIF”** (`imageAvif`, default **on**). Turn it off on a server whose
  GD / Imagick cannot encode AVIF; WebP and the original `<img>` keep working.

Set `webp_quality` / `avif_quality` under `sulu_media.format_manager.default_imagine_options`
(`sulu-base` uses `90` / `90`). **Imagick is recommended in production** for
higher-quality resampling and broader format support; GD works when built with
WebP + AVIF. Sulu's `sulu_media` adapter is `auto` — it uses Imagick when the
extension is present, otherwise GD.

## Credits and AI label

An image tells the visitor two things about itself, in a corner of the box it
is rendered in: who to credit, and whether AI made or modified it. The corner
is the one of the **rendered box**, crop and ratio included, never the one of
the original file: a credit set in the bottom right of a 16:9 photo stays
visible when a 4:3 card crops it.

**The credit** is the **Credits** field of the media library, or its
**Copyright information** when the credits are empty. How it shows is a theme
setting, **Default settings > Images > Image credits**:

| Value | Rendering |
|-------|-----------|
| `overlay` (default) | Laid over a corner of the image, on one line |
| `info` | An "i" mark, the credit unfolding on hover or keyboard focus |
| `caption` | Under the image. Only for an image in the flow of the page: one filling a box (ratio, cover, hero) has no "under" and gets the overlay |
| `none` | Not shown |

**The AI label** follows the **Image origin** field the bundle adds to the
media form, under **License**: *Photo or human-made* (default), *Modified with
AI*, *Generated by AI*. An AI image carries the European Union "AI" icon
([EU icons for labelling AI-generated content](https://digital-strategy.ec.europa.eu/en/policies/eu-icons-labelling-ai-generated-content))
with a translated label, "AI-generated image" or "AI-modified image". The
icon used is the one the EU meant to sit next to a label of the site's own:
the "AI GENERATED" and "AI MODIFIED" variants have their English text drawn
in, so they would read in English on every site. The label is real text, read
by screen readers. The `alt` of the image keeps describing what it shows.

The label answers the deployer duty of the AI Act (article 50): a realistic
image created or edited with AI is labelled visibly, wherever it is shown. It
is on by default, and switched off for the whole project only, in the YAML:

```yaml
itech_world_sulu_tailwind_theme:
    media:
        ai_label: false  # only when the site labels such images another way
```

Both share the corner of **Default settings > Images > Corner of the
credit and the AI label** (`imageNoticePosition`: `bottom-right` by default,
`bottom-left`, `top-right`, `top-left`), the label above the credit. In a hero
under a transparent menu bar, the top corners keep out from under the bar
(`--iw-menu-overlap`).

### Where they show

- Every image of `blocks/common/_image.html.twig`. A credited or AI image is
  wrapped in a `span.iw-media` that takes the classes of its `<picture>` (the
  `<picture>` turns `contents`: it may only hold `<source>` and `<img>`). An
  image with nothing to say keeps its markup unchanged.
- The page hero, the article hero and the editorial blog hero (a background
  picture), over the whole banner, after the title and breadcrumb layers.
- The featured article cards, the wide gallery carousel, the inline image of
  the magazine news style, the mega menu cards and the burger menu picture.
- The picture behind a consent placeholder.
- Every lightbox of the bundle (galleries, text and images, `_image`), in its
  description: the lightbox shows the picture alone, out of its box.
- The structured data of articles and events, as an `ImageObject` (see
  [Structured data](../structured-data.md)).

Avatars carry none: too small for a readable label.

A `raw` image is sized by its caller, so `_image` cannot wrap it on its own.
Its caller says how its notices reach the box:

| `notice` | Use |
|---|---|
| `'parent'` | The caller's positioned element is the box of the image: the notices are laid over it |
| `'wrap'` | A block `span.iw-media.iw-media--wrap` goes around the image. The caller's CSS sizes that span where it sized the `<img>` (the mega menu does it for its horizontal cards) |
| `false` | The caller renders them itself, through `components/_media_notice.html.twig` and `iw_sulu_tailwind_theme_media_notice(media)` |

A raw image given none of them gets no notice. `MediaNoticeRenderTest`
checks that every raw image of the bundle says where they go.

### Small boxes

The notices sit in a size container of their own (`.iw-media-notice`). Under
14rem, the label keeps the icon alone, its text staying for screen readers,
and the credit gets smaller. Under 8rem, they move closer to the corner.
Nothing disappears. The distance to the corner is a margin of
`.iw-media-notice__stack`, not a padding of the layer: a container query
cannot restyle its own container.

### Classes

| Class | Role |
|-------|------|
| `.iw-media` | The rendered box of a credited or AI image, positioned |
| `.iw-media--wrap` | The block wrapper of a raw image (`notice: 'wrap'`) |
| `.iw-media-notice` / `--bottom-right`, `--bottom-left`, `--top-right`, `--top-left` | The layer over the box, and its corner |
| `.iw-media-notice__stack` | The label and the credit, stacked |
| `.iw-media-notice__ai` / `__ai-text` | The AI label and its text |
| `.iw-eu-ai-icon` / `__disc` / `__letters` | The EU icon |
| `.iw-media-notice__credit` / `--info` | The credit, and its "i" form |
| `.iw-media-figure` / `__caption` | An image with its credit as a caption |

### Variables

| Variable | Default | Role |
|----------|---------|------|
| `--iw-media-notice-bg` / `-text` | `rgb(0 0 0 / 0.65)` / `#fff` | Background and text of the label and the credit |
| `--iw-media-notice-inset` / `-gap` / `-z` | `0.5rem` / `0.25rem` / `2` | Distance to the corner, space between label and credit, stacking |
| `--iw-media-ai-size` / `-weight` / `-padding` / `-radius` / `-gap` | `0.75rem` / `600` / `0.1875rem 0.625rem 0.1875rem 0.1875rem` / `999px` / `0.375rem` | The AI label |
| `--iw-media-ai-icon-size` | `1.5rem` | The EU icon |
| `--iw-media-ai-icon-disc` / `-disc-opacity` / `-letters` | `#fff` / `1` / `#1d1d1b` | Its colours: the official "white" variant, which reads on the dark label. For a light label, the "black" one: `#000` / `1` / `#fff` |
| `--iw-media-credit-size` / `-padding` / `-radius` | `0.6875rem` / `0.125rem 0.5rem` / `0.25rem` | The credit |
| `--iw-media-info-size` | `1.375rem` | The "i" mark |
| `--iw-media-caption-size` / `-gap` / `-opacity` | `0.8125rem` / `0.375rem` / `0.75` | The caption |
| `--iw-media-ai-padding-small`, `--iw-media-credit-size-small`, `--iw-media-notice-inset-small`, `--iw-media-ai-icon-size-small` | | The same in small boxes |

```css
/* A light label, the official black icon */
.iw-media-notice {
    --iw-media-notice-bg: rgb(255 255 255 / 0.85);
    --iw-media-notice-text: #111;
    --iw-media-ai-icon-disc: #000;
    --iw-media-ai-icon-letters: #fff;
}
```
