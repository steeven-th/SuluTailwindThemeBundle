# Images — CSS API

Every content image is rendered through the unified partial
[`blocks/common/_image.html.twig`](../twig-reference.md#partial-blockscommon_imagehtmltwig),
which emits a `<picture>` with progressive `avif`/`webp` sources and a fallback
`<img>`. This page documents the two families of static utility classes the
partial (and the blocks that crop images) rely on.

> Conventions: `iw-` prefix for ratio boxes, framework-style `focus-*` for focus
> positioning. See [`../css-conventions.md`](../css-conventions.md).
>
> These classes are **hand-written in `assets/styles/app.css`**, not generated by
> Tailwind — they never need to be added to the `@source inline(...)` safelist.

---

## Aspect-ratio boxes

Applied on the `<picture>` wrapper when the `ratio` param is set. The image
inside fills the box with `object-cover`, so the ratio is enforced without any
inline `style="aspect-ratio"`. The admin ratio pickers only expose this fixed
set of values.

| Class | Ratio |
|-------|-------|
| `.iw-ratio--16-9` | `16 / 9` |
| `.iw-ratio--4-3` | `4 / 3` |
| `.iw-ratio--3-2` | `3 / 2` |
| `.iw-ratio--1-1` | `1 / 1` |
| `.iw-ratio--3-4` | `3 / 4` |
| `.iw-ratio--2-3` | `2 / 3` |
| `.iw-ratio--9-16` | `9 / 16` |
| `.iw-ratio--21-9` | `21 / 9` |

The partial normalises the `ratio` param, so `'16/9'`, `'16:9'` and `'16-9'` all
resolve to `.iw-ratio--16-9`.

To add a ratio, declare a new `.iw-ratio--X-Y` rule in your own stylesheet — no
Twig change required.

## Focus point

Sulu stores a focus point on every media (a 3×3 grid). It is **already applied
server-side** when Sulu crops an outbound format, so the generated thumbnail is
focus-aware. These classes are a **client-side safety net** for the cases where
the crop happens in the browser — an image with `object-cover` that does not
match a server format exactly, or a CSS `background-image`.

Emitted automatically by the image partial (`object-position`) and available for
CSS backgrounds via
[`iw_sulu_tailwind_theme_focus_class(x, y, 'bg')`](../twig-reference.md#iw_sulu_tailwind_theme_focus_classfocuspointx-focuspointy-mode)
(`background-position`).

Grid values: `0` = left/top, `1` = center, `2` = right/bottom.

| `<img>` (object-position) | Background (background-position) | Position |
|---------------------------|----------------------------------|----------|
| `.focus-img-0-0` | `.focus-bg-0-0` | left top |
| `.focus-img-1-0` | `.focus-bg-1-0` | center top |
| `.focus-img-2-0` | `.focus-bg-2-0` | right top |
| `.focus-img-0-1` | `.focus-bg-0-1` | left center |
| `.focus-img-1-1` | `.focus-bg-1-1` | center center |
| `.focus-img-2-1` | `.focus-bg-2-1` | right center |
| `.focus-img-0-2` | `.focus-bg-0-2` | left bottom |
| `.focus-img-1-2` | `.focus-bg-1-2` | center bottom |
| `.focus-img-2-2` | `.focus-bg-2-2` | right bottom |

When the media has no focus point, no class is emitted (the server-side centred
crop is used as-is).

## avif / webp

The partial reads `media.thumbnails['<format>.avif']` and `['<format>.webp']`.
Sulu **always** exposes both keys (its `ImagineImageConverter` lists `webp` and
`avif` unconditionally), encoding each on demand when the URL is first requested.

- **WebP** is served on any modern GD / Imagick build, so its `<source>` is
  always emitted.
- **AVIF** is served only where the server imagine driver was built with AVIF
  support. Because `<picture>` does not retry a source that fails to load, the
  avif `<source>` is gated on the theme toggle **Components → Images → “Serve
  images as AVIF”** (`imageAvif`, default **on**). Turn it off on a server whose
  GD / Imagick cannot encode AVIF; WebP and the original `<img>` keep working.

Set `webp_quality` / `avif_quality` under `sulu_media.format_manager.default_imagine_options`
(`sulu-base` uses `90` / `90`). **Imagick is recommended in production** for
higher-quality resampling and broader format support; GD works when built with
WebP + AVIF. Sulu's `sulu_media` adapter is `auto` — it uses Imagick when the
extension is present, otherwise GD.
